# W4 deviations from `docs/design.md`

Workstream W4 (send: `crates/sbcore/src/tx/*`, `src/py/{playback,sources}.rs`). Phase 0b created every
§12.5 item at its contract signature; phase 1 implemented every body. This file lists everything that
differs from, or adds to, the letter of §12.5 / §12.6, with the reason. No §12.5 signature was changed;
every item below is an addition or an internal shape choice.

## 1. Trait additions (all defaulted, so other implementors are unaffected)

```rust
pub trait PcmProvider: Send + Sync + 'static {
    // … §12.5 methods unchanged …
    /// Atomics only; called when the reader or decoder holding this provider is dropped (§7.4).
    fn on_reader_drop(&self) {}
    /// Atomics only; a panic was caught in the reader/decoder (§5.7): the source ends after one
    /// silent tick, and the housekeeper reports `PlaybackEnded("internal_error")`.
    fn on_poison(&self) {}
    /// The producer failed and everything it produced was played (§7.9 "decode errors close the
    /// stream with decode_error, giving TrackEnded(reason="error")").
    fn failed(&self) -> bool { false }
}

pub trait LiveSource: Send + Sync {
    // … §12.5 methods unchanged …
    /// T5 / worker exit: like `close(Abort)`, but writers then get
    /// `StreamClosed("connection_closed")` (§7.3 step 1 / §4.7 T5).
    fn conn_closed(&self) { self.close(CloseMode::Abort) }
}
```

* **Why `conn_closed`.** `LiveSource::close(mode)` carries no reason, yet §7.3/§4.7 T5 require
  writers to see `StreamClosed("connection_closed")` after a connection closes, and plain
  `StreamClosed("closed")` after a user `close()`. **W2: T5 must call `conn_closed()`** (not
  `close(Abort)`) on every registered source. `Housekeeper::close_all()` already does.
* **Why `failed`.** songbird reports `PlayMode::Errored` only when `Decoder::decode` returns `Err`
  (`mix_logic.rs:96-102`); an `Err` from `next_packet` is a normal end (`Ended`). So when an
  encoded stream's decode thread fails, `PcmDecoder::decode` returns
  `Err(DecodeError("decode_error"))` exactly once, after the already-decoded audio has played. This
  is the only case in which the decoder returns `Err` (§7.1 rule 3 otherwise holds).

## 2. `PcmQueue` internals (all `pub(crate)`; §7.2 shape otherwise kept)

* **Pull epoch in atomics.** `QueueInner.pull_epoch: (u64, Instant)` became two atomics
  (`QueueAtomics::{epoch_pulls, epoch_us}`, µs since queue creation), written only by the
  housekeeper. `stats()`/`heard_ms`/positions are then lock-free (Python properties never take L6);
  a torn read is off by at most one tick. `clear()`/`item()` read the same atomics.
* **Segment bound (§10 G3).** The PCM itself is bounded by `cap_frames`, but per-write segment
  overhead was not: one-frame writes would cost ~48 B of `Seg` + allocation per 2 B of audio. The
  number of queued segments is therefore capped at `max_segs = cap_frames / 32 + 64`; a write that
  would exceed it gets `PlaybackFull` (nothing consumed) exactly like a full buffer, and the
  housekeeper rings the writer once the mixer has consumed segments. Writes of ≥ 32 frames (≤ 4 ms
  at 8 kHz) can never hit this bound before the frame cap.
* **No free on the mixer.** Consumed `Seg::Pcm` boxes go to a fixed-capacity graveyard
  (`QueueInner::dead`, capacity 32, never grown); the housekeeper swaps it with a spare vector under
  L6 and frees the boxes on the RX thread after unlocking. If the graveyard is full (no housekeeper,
  e.g. detached tests) a box is freed inline. The pull path neither allocates nor frees.
* **Housekeeper-only state** (`seen_pulls`, `announced`, the spare vector, …) lives in a separate
  uncontended mutex that is never held while L6 is taken (the state is copied out and back), so
  L6w → L6 remains the only nesting involving L6 (§5.3). Same for `OpusQueue` and L7.
* **Additional private state:** `clock: Clock` (`new` takes it, as in phase 0), `base: Instant`,
  `emit_events` (off for the internal queue of an encoded stream), `QueueInner::{queued_real,
  end_waiting, fresh_turn, last_activity, write_seq, track_playing, stop_sent, dead}`,
  `QueueAtomics::{clears, active}`, `END_FAILED` (`1 << 4`). `PlaybackLimits::idle_ticks` became
  `idle_ms` (idle detection is wall-clock based via the pull epoch, so it also works while parked).
* **`TagId`** carries a slot generation, so a queued segment of an evicted tag never credits the
  tag that reuses its slot.
* **Track state.** `pause`/`resume`, auto-pause and the first write call `track.play()/pause()`
  only when the desired state (`!paused_user && !paused_idle && closed != Abort`) changes; a
  drain-closed queue keeps playing until empty. `attach_track` (called by W2 after `driver.play`)
  brings a freshly attached track to that state, so a write that races ahead of the attach still
  resumes it. `close(Drain)` of a paused (idle or user) track stops it at once, since a paused track
  is never pulled and could not drain.
* **Crate-internal helpers:** `PcmQueue::{new_internal, write_samples, fail, queued_frames,
  free_frames, reader_gone, housekeep_into}`.

## 3. Semantics choices (where §7 leaves room)

* `PlaybackEnded.reason`: `"drained"` (close(drain) + EOF), `"closed"` (abort), `"connection_closed"`,
  `"internal_error"` (caught panic or failed encoded stream), `"stopped"` (the track ended without a
  close, e.g. `TrackHandle.stop()` / `stop_all()`). After `reader_gone` the queue is marked closed and
  freed, so later writes raise `StreamClosed`.
* `PlaybackStarted` is emitted at the first real pull after idle; `PlaybackIdle` only for turns that
  started (a turn cleared before any audio played goes idle silently, still ringing `wait_idle`).
* Underrun is counted only for pulls that tried to pop (not while paused, muted or prebuffering).
* `arm_drain()`/`arm_idle()` return `true` when the queue is closed (the Python layer then checks
  `closed`), so no waiter can hang on a closed stream. `arm_space()` likewise.
* `end_item(tag)` releases the prebuffer gate even if the tag is unknown.
* `MemPcm::from_bytes` rejects a trailing partial frame with `InvalidAudio` ("whole frames").
* `EncodedShared::write`: a write larger than the whole ring is `LimitExceeded`; `PlaybackFull`
  reports `needed_ms = free_ms = 0` (the duration of encoded bytes is unknown); a write after
  `finish()` raises `StreamClosed("closed")`.
* The internal queue of an encoded stream uses `idle_ms = 250` with auto-pause, so a stalled feed
  stops RTP and the next decoded frame resumes it.

## 4. Additions (no contract signature changed)

* `tx::next_source_id()` (phase 0): every live-source id comes from one process-wide counter.
* `encoded::spawn_encoded_with(spec, token, done, send_muted)` and
  `SourceSpec::to_input_with(done, wake, send_muted)`: §12.5's `spawn_encoded` / `to_input` have no
  way to pass the connection's `send_muted` flag (§7.8), so they create an unshared flag. **W2 should
  call the `_with` variants** so encoded streams hold their position while self-muted like every
  other live source.
* `EncodedShared::{attach_track, pcm, is_closed, buffered_bytes}`, `OpusQueue::{attach_track,
  volume, is_closed, reader_gone}`: W2 attaches songbird's handle (or a `FakeTrackControl`) after
  `driver.play`, as for `PcmQueue::attach_track`. The `attach_track`s carry `#[allow(dead_code)]`
  until W2 calls them.
* **Volume ownership (for W2).** Playback and encoded streams apply their volume in `PcmDecoder`
  (5 ms ramp, works while parked), so their songbird `Track` must keep volume 1.0. Opus streams are
  decoded by songbird, so `Track::volume(spec.volume)` applies there (`OpusQueue::volume()`).
* `memory`: the shared buffers are `Arc<Vec<_>>` instead of `Arc<[_]>` (`Arc::from(Vec)` copies, which
  would double the transient memory of a 1 GiB source). `EncodedBytes::data()` now returns `&[u8]`
  (phase-0 accessor). Added `MemPcm::frames()`, `OpusFrames::packet(i)`, and the crate-internal
  `to_input` builders, `MemPcmCursor` (per-track position; the design's `MemPcmReader` is
  `LiveReader` over this provider with `backseek = true`), `MemOpusReader`, `DoneSource`, `ArcBytes`.
* `opus_stream`: `OPUS_IDLE_MS = 250` (the §7.5 idle rule; `OpusStreamSpec` has no `idle_ms`),
  `opus_codec_params()`, `silent_box()`. The reader keeps a 4-entry stash of silent frames, topped up
  from the 64-entry reserve whenever it holds L7, so a contended tick still needs no allocation.
* `Housekeeper::{len, is_empty}`; `add()` tells the new source the current link state.
* `decoder::{pcm_codec_params, DECLICK_FRAMES, VOLUME_RAMP_FRAMES}`; `tx::enter_mixer()` sets
  `Role::Mixer` on a reader's first call (`Role::Unknown` threads only) and debug-asserts the
  caller is not a Python thread.
* Logging: a caught mixer panic is logged at ERROR by the housekeeper (never on the mixer), and an
  encoded decode failure/panic by the decode thread.

## 5. Binding (`src/py/{playback,sources}.rs`) — unchanged from phase 0

* `Playback.write(data, tag=None, at_ms=None) -> None` and `write_base64(data: str | bytes, …)`.
  `close(drain=False)`. The `volume` setter takes the value as an object (stub type `float`) and
  extracts it, because pyo3-stub-gen 0.23.1 cannot generate a setter that also takes `Python<'_>`.
* `EncodedSink` (§12.6 lists no members): `write(data)`, `arm_space(nbytes)`, `finish()`,
  `close(drain=False)`, `wake_id`, `track`. `OpusSink`: `send(packet)`, `arm_space()`, `clear()`,
  `buffered_ms`, `close(drain=False)`, `wake_id`, `track`. Both (and `Playback`) are `weakref`. On drop
  they close with `Abort` **unless a drain was already requested** (`close(drain=True)`, or
  `EncodedSink.finish()`): that drain then completes and the track ends on its own (see §7).
* `ClearResult.items` is a `tuple[ItemProgress, ...]`; `ItemProgress` holds `Arc<ItemProgressData>`;
  `ClearResult` holds `Arc<ClearSummary>`; `PlaybackStats` holds the `Copy` `PlaybackStatsData`.
* Sources: `AudioFile(data)`, `AudioFile.from_path(path, *, max_bytes=256 MiB)` (read + probe under
  `py.detach`), `AudioFile.from_arrow(array)`; `RawPcm(data, format)`, `RawPcm.from_samples(...)`
  (Arrow input detected by `__arrow_c_array__`), `OpusPackets(iterable)` (enforces `MAX_OPUS_PACKETS`
  / `MAX_SOURCE_BYTES` while iterating). The Arrow constructors go through W3's `py/arrow.rs` import
  helpers, which raise `SongbirdError("built without the 'arrow' feature")` without the feature.
  `AudioFile.load` is async and belongs to the Python layer (W5).
* Numeric arguments are checked before narrowing (`LimitExceeded`, not `OverflowError`).
* **G1 letter / §4.3.** `Playback`, `EncodedSink` and `OpusSink` hold, besides their `Arc<…>`, a
  `track: TrackRef` (two `Arc`s) and a `conn: Weak<ConnShared>` — the pair §4.3 lists for
  `NativeTrack` — because §12.6 gives them a `track` member. No Python object is held (I1).

## 6. Integration notes for W2 / W5

*Wired in phase 2; see `I1.md` §1 (`spawn_encoded_with`/`to_input_with` also take the connection's
`Clock`; the internal queue of an encoded stream keeps a user-paused drain; `LiveSource` gained
`set_user_paused`/`set_source_volume`).*

* `ConnShared::open_playback`: `PcmQueue::new(next_source_id(), …)`, `live_pcm_input(q, done,
  false)`, `driver.play(Track::new(input).pause())` (volume 1.0), then `q.attach_track(handle)` and
  register `Arc::downgrade(&q)` with the housekeeper. Same pattern for `open_opus_stream`
  (`opus_stream_input`) and `open_encoded` (`spawn_encoded_with`, then `enc.attach_track`).
* Detached mode: attach a `FakeTrackControl`; `MixerHarness` can destructure the `Input` built by
  `live_pcm_input` (`Input::Live(LiveInput::Parsed(p), None)`) and drive `p.format.next_packet()` →
  `p.decoder.decode()`, as `tx::decoder::tests::Mixer` does.
* The housekeeper calls `LiveSource::housekeep`, which emits `PlaybackStarted/Idle/Ended` through
  `EventHub::emit` (a W2 stub until phase 2; the tx unit tests observe the events through
  `PcmQueue::housekeep_into`).

## 7. Adversarial review fixes (W4 review pass)

Each fix has a unit test that fails without it.

*Phase 2: the decode thread no longer probes a stream closed before its first byte (symphonia
logged `probe reach EOF at 0 bytes` at ERROR for a normal close); see `I2.md` §1. A close that lands
during the probe mutes symphonia's report on that decode thread, and `DecodeThread` is counted from
the spawn; see `I3.md` §4.*

* **A close before `attach_track` was lost.** `close()` marked `stop_sent` even when no track was
  attached yet, so a playback/Opus stream closed (by T5, or drain-closed while never written)
  between `driver.play` and `attach_track` was never stopped and stayed paused in the mixer until
  teardown. `close()` now leaves the stop to `attach_track` when no track is attached, and
  `attach_track` applies the same rule as `close()` (`Abort`, or `Drain` of a track that is not
  playing → `stop()`). Same for `OpusQueue`.
* **Encoded decode thread gave up on a full segment table.** The internal queue's segment bound
  (`cap_frames / 32 + 64` = 1 564 segments) can be reached before its frame cap by a codec with
  tiny packets (e.g. FLAC with 16-frame blocks). `push48` treated that `PlaybackFull` as "closed" and
  the thread exited without closing anything, so the stream hung (never ended, never decoded more).
  It now waits for the next housekeeping tick (`wait_tick`, bounded and woken by `close()`) and
  retries.
* **Corrupt packets were counted over the whole stream.** A long stream with sporadic undecodable
  packets (an MP3 joined mid-stream, a radio stream) failed after 64 errors in total. The limit now
  applies to packets **in a row** (`MAX_BAD_PACKETS_IN_A_ROW`).
* **`MemPcm::from_any_rate` sized its output after allocating.** Upsampling (e.g. 8 001 Hz → 48 kHz)
  multiplies the input by up to 6, and the `MAX_SOURCE_BYTES` check only ran on the finished result.
  The expected 48 kHz size is now checked before any buffer is allocated (§10 validation rule).
* **Connection close did not wake waiters.** `EncodedShared::conn_closed` now rings its token
  (writers waiting for ring space get `StreamClosed("connection_closed")`), and
  `PcmQueue::conn_closed` rings an armed end waiter; `PcmQueue::arm_end()` reports a closed
  connection as ended (its reader goes with the Driver after the housekeeper has stopped, so nothing
  would ring later).
* **Link-down discard did not start a new turn.** `on_link(false)` with `when_disconnected=discard`
  now sets `fresh_turn` like `clear()`, so the prebuffer gate re-arms for the first reply after the
  reconnect.
* **Dropping a handle after `finish()` / `close(drain=True)` aborted the drain.** New
  `PcmQueue::abandon()`, `OpusQueue::abandon()` and `EncodedShared::abandon()` (used by the pyclass
  `Drop`s) abort only when no close was requested. In particular an `EncodedSink` whose feed
  finished (`feed_from(..., finish=True)`, `enqueue_stream`) can be dropped without cutting off the
  audio still in the ring and the decoded lookahead. `EncodedShared::is_finished()` was added.
  The class docstrings changed, so `py-src/discord/ext/songbird/native/__init__.pyi` was regenerated
  with `cargo run --bin stub_gen` (only those three docstrings differ).

Known, not changed (design-level):

* `timed_end_ms` is the maximum over the playback's lifetime (§7.2). If one playback is reused across
  provider sessions whose timeline restarts at 0, a later `clear(reject_until_gap_ms=…)` sets
  `cut_end_ms` to the old session's end and rejects the new session's timed writes until its
  timeline passes it. The examples open one playback per session, which avoids this.
* `spawn_encoded` has no clock parameter, so an encoded stream's internal queue always uses the real
  clock (idle detection under a detached `ManualClock` harness compares two clocks).

## 8. Memory review fixes (bounded buffer extraction)

* **Encoded-byte extraction had no cap.** `convert::extract_bytes` copied any non-`bytes` buffer in
  full before sbcore checked its size, so `EncodedStream.write`, `OpusPacketStream.send`,
  `AudioFile(data)` and `OpusPackets` items allocated and copied (GiBs for an `mmap`) only to raise.
  `extract_bytes` now takes a `MaxBytes` like `extract_audio` (no extraction is uncapped): the ring
  cap (`EncodedShared::max_write_bytes`, `LimitExceeded("write_bytes")`), 1275 bytes per Opus packet
  (`InvalidAudio` with sbcore's `OPUS_PACKET_SIZE_MSG`) and `MAX_SOURCE_BYTES`
  (`LimitExceeded("source_bytes")`). The cap is checked for `bytes` too, so `AudioFile(bytes)` no
  longer copies a > 1 GiB input before rejecting it. Observable order change: an oversized write to
  a closed `EncodedStream` raises `LimitExceeded` rather than `StreamClosed` (as `PlaybackStream`
  already did).
* **Redundant source copies.** `RawPcm(bytes, …)` and `RawPcm.from_samples(bytes, …)` copied the
  borrowed `bytes` before parsing; they now parse from the borrow (peak 1× instead of 2×).
  `OpusPackets(iterable)` copied every item into its own `Vec` and then concatenated them;
  `OpusFramesBuilder` now validates and appends each item to the shared buffer (and `from_arrow`
  appends straight from the Arrow buffer), releasing the growth slack at the end.
* **`EncodedStream.feed_from` re-sliced every chunk into a `memoryview`**, so every write (and every
  `PlaybackFull` retry) was copied natively before the ring copied it again. `bytes` chunks that fit
  `chunk_size` are passed through; `EncodedStream.write` turns a retried non-`bytes` buffer into one
  `bytes` copy (it already passed the cap check) that later attempts borrow.
* Tests: `test_bounds.py` (oversized `bytes`/`bytearray`/`memoryview`/`mmap` for every entry point,
  RSS growth for `RawPcm` and `OpusPackets`), `test_sources.py::
  test_encoded_stream_copies_each_write_at_most_once`, and the sbcore unit tests
  `opus_frames_builder_copies_once_without_slack` and `ring_limits_and_space_wakeups`.
* Not changed: `PlaybackStream.write` retries still re-copy a non-`bytes` buffer per attempt (each
  copy is bounded by `max_write_bytes`).
