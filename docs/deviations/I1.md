# I1 deviations: phase-2 Rust integration

Task I1 wired the phase-1 workstreams (W2 connection, W3 receive, W4 send, W5 test hooks) together
in `crates/sbcore` and the binding. This file lists what the integration added to, or changed in,
the phase-1 contracts and the W2–W5 deviation files, with the reason. The integration notes in
`W2.md` §9, `W3.md` §0, `W4.md` §6 and `W5.md` §2 are resolved as described here.

## 1. Send path (`ConnShared`, §4.9, §7)

* **Inputs are built with the W4 `_with` constructors.** `open_playback` uses `live_pcm_input`;
  `open_encoded` uses `spawn_encoded_with(spec, token, done, send_muted, clock)`;
  `open_opus_stream` uses `opus_stream_input`; `play()` and queue entries use
  `SourceSpec::to_input_with(done, wake, send_muted, clock)`. Every live source is handed to
  songbird **paused** and gets its control through `attach_track` (`PcmQueue`, `OpusQueue`,
  `EncodedShared`), so its first accepted write / packet / decoded frame resumes it.
* **Track volume.** Playback and encoded streams start their songbird track at volume 1.0 (their
  decoder applies the volume, W4.md §4); Opus streams carry `OpusQueue::volume()` on the track.
* **Clock parameter (addition).** `spawn_encoded_with` and `SourceSpec::to_input_with` take the
  connection's `Clock`, so an encoded stream's internal queue (idle detection, positions) uses the
  same time base as the housekeeper; a detached `ManualClock` harness is now consistent.
  `spawn_encoded` / `to_input` (the §12.5 contract) still use `Clock::Real`.
* **Lazy encoded queue entries are live sources (§4.9).** When such an entry becomes current it is
  spawned with the entry's *current* volume (pending `set_volume` changes apply), started paused at
  track volume 1.0 and attached; `loops` does not apply to it (live sources cannot loop).
  `paused=True` sets the internal queue's user pause, so decoded audio waits for `resume()`. It is
  registered for T5/the housekeeper before songbird gets it, and closed if the start fails.
* **The internal queue of an encoded stream keeps a user-paused drain (change).** Its end of input
  (`close(Drain)`) no longer stops a **user-paused** track that still holds audio
  (`PcmQueue::hold_paused_drain`, set for internal queues only): a paused queue entry would
  otherwise end `stopped` before it ever played. `PlaybackStream` keeps W4's rule (a drain-close of
  a paused playback stops it).
* **`TrackHandle` controls of live sources go through the source (addition).** `TrackRef` gains
  `live: Arc<OnceLock<Weak<dyn LiveSource>>>` (set for playbacks, `open_encoded` streams and lazy
  encoded entries). `pause`/`resume` then set the source's own user pause and `set_volume` its
  decoder volume: a direct songbird pause would be undone by the source's next auto-resume, and a
  songbird volume would multiply with the decoder's. `LiveSource` gains two defaulted methods,
  `set_user_paused(bool) -> bool` and `set_source_volume(f32) -> bool` (`false` = use the songbird
  handle; Opus streams keep using it). Queue `pause()/resume()` and late changes of an entry being
  started use the same path.
* **T5 calls `LiveSource::conn_closed()`** (W4.md §1), as does `add_source` when the connection is
  already closing; writers get `StreamClosed("connection_closed")` and waiters are woken.

## 2. Limits (I6, §4.8 preallocated tracks)

* `ConnShared.sources` records whether a source counts towards `MAX_LIVE_SOURCES_PER_CONN`
  (`open_*` only). A lazy encoded queue entry is the queue's current entry and counts towards
  `MAX_PLAYING_TRACKS_PER_CONN` instead (`TrackQueue::live_current`, added to the admission count
  next to `TrackRegistry::playing`). songbird therefore never holds more than 16 + 32 = 48
  (= `PREALLOCATED_TRACKS`) tracks; before, an encoded entry was in neither limit (49 possible).
* **`MAX_SUBS_PER_CONN` admission moved into `WorkerShared::reserve_sub` (change).** Explicit
  subscriptions and router-created streams share one race-free admission over `open_queues()`;
  before, the router checked only the pipeline's own subscription count.

## 3. Receive path (§8)

* `ConnShared::new_pipeline` calls `RxPipeline::attach_worker` (initial pipeline and the rebuild
  after a caught worker panic): router-created streams are budget-checked
  (`reserve_budget`), registered for T6 (`register_queue`), admitted by `reserve_sub` and removed
  through `RemoveSub`.
* `subscribe_router` validates with `RouterSpec::validate` and refuses a router whose single stream
  could never fit `max_receive_mb` (`LimitExceeded("max_receive_mb")`).
* **`ReceiveStalled` is emitted by the ConnWorker only, once per stall** (W2.md §4). The pipeline's
  own emission was removed (it fired a second event per stall). `since_ms` keeps W3's meaning: the
  receive-timeline position (whole ticks since `t0`) where the stall began, i.e. the last real
  tick or the link-up (`ConnShared::timeline_ms_at`). W2's worker had reported the stall's age.
* The `unclassified` list stays bounded by the pipeline (`MAX_CLASSIFY`, W3.md §2).

## 4. Events and stream close (§8.11, §6.5, §4.9)

* **`Lagged` is synthesised whatever the queue's kind mask (change, the design's letter).** W2.md §5
  synthesised it only for masks selecting `Lagged`; §8.11 says "after drops, a synthetic
  `Lagged{dropped}` precedes the next delivered event", and the Python tests (a stream filtered to
  `UserMapped` must learn about drops) rely on it. The `events.rs` unit tests that asserted the old
  rule were changed accordingly.
* **A subscriber's close is first-close-wins for clearing too (change).** `SubQueue::close_and_clear`
  (`ReceiveSubscription.close()`/drop) and `EventQueue::close()` free the queued items only when
  they close the queue. On a queue that T6 (or `UserLeft`, an overflow) already closed they do
  nothing: `SongbirdClient.cleanup()` closes every child stream right after `conn.close()` (§6.5),
  and the chunks / the final `Disconnected` that T6 left readable must still drain (§4.9, §8.11).

## 5. Panics (§5.7)

* `stats()["panics"]` = caught worker-step panics + caught dispatcher panics + tracks whose reader,
  decoder or decode thread caught a panic. The latter are marked with a new `TrackFlags` hint bit
  `PANICKED` (atomics only, set on the mixer / decode thread) and counted once when their
  `TrackEnded` is reported (`TrackRegistry::panics`). `dispatch_panics` is still reported alone.

## 6. Test hooks (§13.2)

* **One parking lot.** Detached connections now park inputs and register fakes in the test hooks'
  process-wide tables (`testing::registry`, keyed by the connection), so `Harness::{step,
  parked}`, `MixerHarness`, `track_log` and `conn::take_parked_live_input` all see what the
  connection parked. W2's per-connection lot (`DetachedState.parked`) and its `SharedFake` were
  removed. A track parked after the connection closed is dropped at once (T8 already disposed of
  the rest); every park first disposes of the inputs of ended tracks (bounded).
* **`FakeTrackControl` keeps the pause state** (`with_paused(flags, paused)`, `is_paused()`), so the
  `TrackRef`'s fake and the control handed to the source are one object; W5's `SharedFake` wrapper
  is gone. Memory tracks are handed over in their `paused=` state (no `"pause"` call is logged
  for them any more).
* **A fake `stop()` while the connection is closing does not resolve the track**, like a songbird
  handle whose Driver is gone: T8 then resolves it `disconnected` (it used to end `stopped` when
  T5's `conn_closed` stopped a detached live source).
* `inject_driver_event` uses the `Dispatch` handler's own path (`apply`, then `LinkUp`/`LinkDown`
  through `send_ctrl`, with its overflow queue) instead of W5's copy. `inject_tick`/`inject_map`/
  `inject_user_left` keep using the same tick-channel sender (`ConnShared::rx_sender_ref`); W5's
  duplicate accessor `ConnShared::test_rx_sender` (W5.md §1) was removed.
* `Harness::detached` works on `ConnShared::new_detached` and turns the detached auto-connect off:
  no Driver runs the connect future, so the state stays `connecting` until the test injects the
  outcome (`DriverEvent::Connect` / `ConnectFailed`), as W5.md §3 specifies and the Python tests
  expect. (`ConnShared::new_detached` alone keeps W2's instant connect for W2's unit tests.) Its
  contract test now requires success and is serialised with the live-counter tests.

## 7. Fork safety (§4.10)

* `Subscription` and `RouterHandle` (`Drop`), and the binding's `Playback`, `EncodedSink`,
  `OpusSink` (`Drop` and `close()`), `ReceiveSubscription.close()` and
  `RouterSubscription.close()` take no lock in a forked child (the `EventSubscription` pattern):
  the handles are simply freed.

## 8. Tests

* `crates/sbcore/tests/detached_integration.rs` (feature `test-hooks`): receive (injected RTP →
  per-user 24 kHz and 8 kHz µ-law, mixed 16 kHz, exact chunk sizes, contiguous timelines, stream
  clocks, speaking metadata, synthesised silence, `ReceiveStalled` once, budget release), the
  router (budgeted, registered, `close_on_leave`), playback through `MixerHarness` (paused until
  written, exact 48 kHz samples, 24 kHz → 48 kHz level and frequency, underrun, `clear()` within
  one tick, positions, `PlaybackStarted/Idle/Ended`, drain → `finished`), Opus streams, memory
  tracks and the queue with fakes, lazy encoded entries (decode, resume on the first frame, play
  out, `paused=True`), the 48-track bound, and `close()` during activity (everything closed
  synchronously, every live counter back to its baseline), plus writers and the mixer racing
  `close()`.
* Unit tests: a worker-step panic closes the streams with `internal_error`, counts in `panics` and
  rebuilds the pipeline; `PANICKED` is set by a panicking reader and counted once; the queue's
  encoded entry starts paused and counts as `live_current`; closing an already closed receive or
  event queue keeps its contents; `Lagged` regardless of the mask. The fork test now waits for an
  earlier test's Driver to finish closing before counting Drivers (a load-dependent flake).
* **Python tests fixed because they contradicted the design** (found by running the suite against
  a `--features test-hooks` build of this commit; with the fake module nothing changes):
  `test_clear_is_immediate` asserted `res.item(tag) is item` (identity would need a stored Python
  object, I1; it now compares fields); `test_speaking_and_speakers` required the chunk right after
  a user's last packet to be digital silence, but the 48 → 24 kHz converter's documented ~1.3 ms
  delay (w1.md §2) carries the packet's tail into it (it now checks the next chunk);
  `test_full_lifecycle_returns_to_baseline` kept `pytest.raises`'s `ExceptionInfo`, whose
  traceback holds `connect()`'s frames and so the client (it is now deleted).
* With these fixes the whole Python suite passes against the real module built from this commit
  with `--features test-hooks` (CPython 3.14t, `PYTHON_GIL=0`, `SONGBIRD_TEST_NATIVE=real`): 308
  passed, 3 skipped (the `fake_only` tests); against the fake: 306 passed, 5 skipped.
