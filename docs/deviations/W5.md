# W5 deviations from `docs/design.md`

Workstream W5 (Python layer, test hooks, tests, examples, docs, CI, packaging). This file lists
everything that differs from, or adds to, the letter of the design, plus what the integration phase
must wire up. Each entry gives the reason.

## 1. Change outside W5's files (shared with W2)

* **`crates/sbcore/src/conn/shared.rs`** (W2) — one test-hooks-only accessor appended at the end of
  the file:

  ```rust
  #[cfg(feature = "test-hooks")]
  impl ConnShared {
      pub(crate) fn test_rx_sender(&self) -> Option<&RxSender> { self.rx_tx.as_ref() }
  }
  ```

  §13.2 requires `inject_*` to feed "the same `RxSender` … that `Dispatch` uses", but the §12.3
  facade exposes no way to reach it (`rx_tx` is private and `new_detached` returns only
  `(Arc<ConnShared>, ConnWorker)`). Nothing else in W1–W4 files was changed.

## 2. Detached-mode contract for `ConnShared::new_detached` (W2, integration)

*Wired in phase 2; see `I1.md` §5 (`FakeTrackControl` keeps the pause state itself, so
`SharedFake` is gone; `ConnShared::test_rx_sender` of §1 was removed in favour of W2's
`rx_sender_ref`).*

`crates/sbcore/src/testing/` is written against the §12.3 contract; with W2's stub bodies the
`detached` constructor surfaces `Internal("unimplemented")`. To make the harness work, W2's detached
connection must, wherever a Driver-backed connection calls `driver.play(track)`:

1. attach `sbcore::testing::fake_track_control(&flags)` as the track's `TrackControl` (live sources:
   `PcmQueue::attach_track`, `OpusQueue`/encoded equivalents). It wraps W4's `FakeTrackControl` in an
   `Arc` registered by flags identity, so `track_log(track)` can find the log;
2. hand the songbird `Input` it built to `sbcore::testing::park_input(conn, source_id, flags, input)`
   (`source_id` = `LiveSource::id()` for live sources, `None` for memory/file tracks).

`MixerHarness::take(playback)` looks the parked input up by `LiveSource::id()`. `Harness::step`
disposes of the inputs of ended tracks (all of them once the connection is closed) and dropping the
`Harness` disposes of whatever is left — the `DoneGuard` paths songbird would run. With no Driver,
a detached connection's `Connect` action has nothing to execute; the harness supplies the connect
future's outcome (§3 below).

## 3. Test-hook API (W5 files; the phase-0b skeleton signatures were W2's suggestions)

* `testing::Harness::detached(guild, user, settings, bell, reconnect: bool)` — `reconnect` added so
  tests can exercise `reconnect=False` terminal transitions. Python:
  `detached_connection(guild_id, user_id, settings, bell=None, *, reconnect=True)`.
* `Harness::step(advance_ms)` runs one `ConnWorker::step` at the current manual time (processing
  whatever was injected), then advances the clock in increments of at most 20 ms (earlier if the
  worker asks to be woken sooner, never below 1 ms), running one iteration after each, so per-tick
  housekeeping and timeline synthesis behave as on the real RX runtime. Bounded:
  `0 <= advance_ms <= 3_600_000`. Additions: `Harness::{elapsed, parked}`; Python `Harness.elapsed_ms`,
  `Harness.parked`.
* `DriverEvent::ConnectFailed { timed_out }` (Python kinds `"connect_failed"` / `"connect_timeout"`).
  `DriverEvent::Connect { ssrc }` applies `DriverConnect{ssrc}` and then — only while the state is
  `connecting` — the connect future's `ConnectResult{generation: status().generation, Ok}`, because
  per §4.5 `DriverConnect` alone never leaves `Connecting`. This assumes the generation of
  `Phase::Connecting` equals `StatusSnapshot::generation` (W2: keep them equal, or expose the
  in-flight generation).
* `inject_tick` wraps each payload with `rtp::rtp_wrap` using consecutive per-SSRC sequence numbers
  (a lost voice consumes one), so the pipeline sees exactly what songbird's Decrypt mode delivers.
  All injected packets — and `rtp_wrap`'s output — carry the 20-byte AEAD suffix (16-byte tag +
  4-byte nonce) of songbird's rtpsize modes: `payload_offset = 0`, `payload_end = payload.len() − 20`
  (`rtp::payload_bounds`), which catches any treatment of `payload_end` as a length.
* A full tick channel makes `inject_*` raise `LimitExceeded("tick_channel")` (step the harness)
  instead of silently counting a drop like `Dispatch`; a closed channel drops the input like
  `Dispatch`. `RawTick.arrived` uses the detached connection's manual clock.
* `MixerHarness` additions: `take_source(source_id)`, `pulls`, `ended`, `end_error`, `channels`,
  `drop_track()`; Python `MixerHarness.pulls/ended/channels/drop_track()`. songbird does not pull a
  paused track, so the harness reads the fake control's log (`pause`/`play`, initially paused) and
  returns silence without pulling while paused; a track whose flags resolved is disposed of before
  its next pull. `pull` is bounded to 3 000 ticks per call.
* `alloc_count()` counts only `next_packet` + `decode` + the copy into a pre-reserved buffer, which
  `MixerHarness::pull` runs inside the per-thread counting guard.
* Bounded test-only tables (`testing/registry.rs`): ≤ 1 024 connections of injection state, ≤ 4 096
  parked inputs (a further input is dropped at once: its track ends), ≤ 65 536 fake-control logs.

## 4. Python layer

* **`AudioFile.load` → `load_audio_file(path, *, max_bytes)`** (module function, also exported from
  `discord.ext.songbird`). §9.8's async classmethod cannot be added from Python: `native.AudioFile`
  is a frozen, non-subclassable pyclass (W4's note assigned `load` to W5). W4 may add a native
  classmethod returning `asyncio.to_thread(AudioFile.from_path, path, max_bytes=…)`; the helper can
  stay as an alias.
* **`open_playback(max_gap_ms=None)`**: `None` means `min(2000, max_buffer_ms // 2)`. With the
  §9.4 default of 2 000, any `max_buffer_ms < 4000` failed the §12.2 cross-field rule
  (`LimitExceeded("max_gap_ms")`) unless the caller also lowered `max_gap_ms`.
* **Stale leave echo (refines §6.2/§6.3).** A `VOICE_STATE_UPDATE` with `channel_id=None` that
  arrives before the gateway has placed the client in a channel for this connection is not forwarded
  to the state machine: it can only be the echo of an earlier leave (e.g. the best-effort leave of an
  aborted connect that the next `connect()` awaited before its join). Forwarding it closed the new
  connection with `left_channel` (found by `test_stale_leave_never_follows_the_new_join`).
* **`discord.types.voice` is imported only under `TYPE_CHECKING`**: at runtime it imports
  `typing_extensions`, which discord.py 2.7.1 does not depend on.
* Wait semantics assumed for W4's `arm_*` methods: each returns `True` when the awaited condition
  already holds (`arm_space(n)`: room for `n` bytes; `arm_drain()`: drained; `arm_idle()`: the stream
  is idle, so `wait_idle()` returns at once when nothing is playing; `arm_end()`: the reader is gone)
  and otherwise arms the stream's wake id. If `arm_space` reports room but the write still does not
  fit (it also needs inserted gap silence, or another thread took the space), `write()`/`send()`
  yield to the loop on the first retry and wait one tick on later ones — they never spin
  (`PlaybackStream`, `EncodedStream` and `OpusPacketStream` alike).
* `PlaybackStream.format` is kept by the Python wrapper (`native.Playback` has no format getter).
  `EncodedStream`/`OpusPacketStream.aclose(drain=True)` wait on `track.wait_ended()` (the sinks have no
  `arm_end`).
* Additions: `TrackHandle.pending`, `TrackQueue.__bool__`, `discord.ext.songbird.UserLike`,
  `streams.kind_mask()`/`user_id()`/`user_ids()`, `_log.logger_name()`/`is_running()`.
  `SongbirdClient._open_connection(bell, settings, reconnect)` is the (private) seam tests override
  to build a detached connection.
* The hand-written `py-src/discord/ext/songbird/__init__.pyi` was deleted (§14 item 11).

## 5. Tests

* `tests/fakes/native_fake.py` models the observable native contract (signatures, error types and
  constructor arguments, arming/wake protocol over a real socket doorbell, the §4.5 state machine
  subset the client uses, timeline synthesis and debt, queue bounds and overflow policies, PcmQueue
  write/clear/tags/gap filling/prebuffer/idle, tracks and queue). It replaces Opus with a toy codec
  (`_testing.encode_opus` packets carry 8 kHz µ-law) and its encoded stream "decodes" bytes per tick
  without a mixer.
* `SONGBIRD_TEST_NATIVE=auto|real|fake` selects the module (`tests/conftest.py`). With the fake:
  306 passed, 5 skipped. The skipped `real_only` tests (zero-allocation mixer pulls, token never
  logged, loop jitter under 20 speakers, real-Driver lifecycle back to `_debug_live_counts()`
  baseline, RSS growth over 100 cycles) and the whole suite run against the real module once it is
  built with `--features test-hooks` (integration phase).
* discord.py objects are faked, but `Connectable.connect` is discord.py's own implementation
  (`discord.abc.Connectable.connect(fake_channel, …)`), so the §6 contract is exercised for real.

## 6. Tooling and packaging

* **ty**: `extra-paths = ["py-src"]` was removed. ty 0.0.92 resolves `discord` to the `py-src/discord`
  namespace directory listed there instead of discord.py's regular package. The package is found
  through the editable install (`maturin develop` writes a `.pth`), so CI installs it before `ty check`.
  ty now also checks `tests/` and `scripts/`.
* **ruff**: rules `F` + `I` (was `I`); `tests/` and `scripts/` included; the generated
  `py-src/discord/ext/songbird/native/` is excluded (formatting it would make the stub-drift check
  fail).
* `pyproject.toml`: pytest `testpaths`, markers and a filter for discord.py's own
  `asyncio.iscoroutinefunction` deprecation warning; `[tool.maturin] exclude` keeps `tests/` and
  `examples/` out of wheels/sdists; free-threading and typing classifiers.
* `ci.yml` adds a `python-fake` job (the Python suite without building) next to the §13.7 jobs;
  `release.yml` runs `scripts/smoke.py` for wheels and both sdist builds.

## 8. Review fixes (adversarial review of the W5 commit)

Behaviour refinements of §6 (Python layer), each with a regression test:

* **No join after a leave or close.** `SongbirdClient._may_join()` gates every op 4 that puts the
  bot in a channel and that the library sends on its own or later: the rejoin task of
  `Control.Rejoin` (checked before its leave and again before its join), the flag flush of §6.7,
  `reconnect()`'s join and `move_to()`. Once `disconnect()` has started (`_leave_sent`), the client
  is finalized or the connection is closed, none is sent; `cleanup()` also cancels the in-flight
  helper tasks. Before, a rejoin in progress (or a `set_self_mute()` racing `disconnect()`) could
  send its join after the user's leave and leave the bot in the channel with nothing registered
  (`test_disconnect_during_a_rejoin_never_rejoins`, `test_flag_change_during_disconnect_sends_no_join`).
* **The owed leave of an aborted connect survives a cancelled `connect()`.** §6.2 awaited it with
  `asyncio.wait_for`, which also cancels it when the *new* `connect()` is cancelled, so the leave was
  never sent. It is now awaited with `asyncio.wait` (still cancelled on its own 5 s timeout, so it is
  never sent after the new join) and re-registered in `_pending_leaves` when the waiter is cancelled.
  A leave left behind by another event loop is ignored (it can be neither awaited nor cancelled
  from this loop).
* **Best-effort leave after a terminal failure.** When an established connection closes with
  `connect_failed`, `rejoin_failed`, `lost`, `session_invalid` or `internal_error`, the last op 4
  the client sent was a join, so the gateway still lists the bot in the channel. `_finalize()` now
  schedules the same best-effort leave as `_abort_connect()` (registered in `_pending_leaves`, sent at
  most once). Kicks and `left_channel` send nothing (already out); `requested` already sent one.
* **`TrackQueue` no longer references the client** (it took the client's bound `_spawn`, a
  client ↔ queue reference cycle that kept an abandoned client alive until the cyclic GC ran). It
  owns its feed tasks; a queued stream's feed ends quietly on `StreamClosed`/`ConnectionClosed`
  (it used to be logged as an ERROR at every disconnect) and `cleanup()` cancels feeds that are
  still waiting on their source.
* `examples/music.py`: `!play` paths must resolve inside `MUSIC_DIR` (chat users could make the bot
  open any local file), only `!play`/`!stream` join a channel, and the title table drops ended
  tracks.

Test hooks (W5 Rust files):

* **`MixerHarness` pause state.** It was derived from the `FakeTrackControl` call log, which stops
  recording after `LOG_CAP` (4 096) calls, so after many auto-pause/resume cycles (e.g.
  `test_writers_and_clear_race_the_mixer` on the real module) the harness froze in whatever state
  the 4 096th call left. `testing/registry.rs` now wraps the fake in a `SharedFake` that also keeps
  the pause state (`AtomicBool`, initially paused) on every `pause`/`play`; `track_log` still reads
  the bounded log.
* **`Harness::step(n)` advances the manual clock by exactly `n` ms.** A sub-millisecond worker
  wake-up was rounded up to 1 ms even when less than 1 ms of the step remained, overshooting the
  target (`next_increment`, unit-tested).
