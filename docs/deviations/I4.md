# I4: API, docs and tests review fixes (2026-10-27)

Fixes from the review of the public API, the user docs and the test suite. Each changes behaviour
only where the design text already said otherwise, or records a refinement of it; `docs/design.md`
is updated in the same change.

## 1. Library

* **The leak oracle sees a Driver that was never Poisoned** (§11.3). `_debug_live_counts()` also
  reports `net_alive_tasks` and `rx_alive_tasks` (tokio's `num_alive_tasks()` of the NET and RX
  runtimes; 0 before a runtime exists, never starts one). None of the instance counters could tell
  whether `OwnedDriver::teardown` really Poisoned the Driver: `OwnedDriver` drops when `teardown`
  returns, songbird's events task drops every `Dispatch` clone on `RemoveGlobalEvents`, the mixer
  drops every `SongbirdInput` on `SetTrack(None)`, and `live_tasks()` counts live mixers only. A
  never-Poisoned Driver keeps 3 NET tasks (core runner, events runner, the parked mixer's forwarder;
  plus WS/UDP when connected). songbird also keeps **one process-wide NET task once its first Driver
  has run** (besides the scheduler's Idle task; constant, not per Driver), and process-wide helper
  tasks may start lazily, so leak tests take their baseline after a warm-up cycle and compare task
  counts with `≤`.
  * Rust: `real_driver_lifecycle_tears_everything_down` asserts the NET tasks rise by ≥ 3 and return
    to baseline (a `mem::forget(d)` in `teardown` fails it: 8 vs 2).
  * Python: `test_full_lifecycle_returns_to_baseline` (warm-up cycle, then 5 real-Driver cycles that
    must each raise `OwnedDriver` and `net_alive_tasks` by ≥ 3); the 100-cycle test also warms up.
* **`receive=False` keeps `UserMapped`/`UserLeft`** (§8.5, §9.3). The tick channel used to be
  closed from the start without receive, so the `Dispatch` threw away every `Map` and `UserLeft`
  although it still registers `SpeakingStateUpdate`/`ClientDisconnect`. It is open now; no
  `VoiceTick` handler is registered and the pipeline (`enabled=false`) ignores ticks, so
  `SpeakingStarted`/`SpeakingStopped` still never fire (they need audio).
* **`enqueue_stream(loops=…)`**: any value but 0 raises `TrackError("live sources cannot loop")` at
  enqueue (`TrackQueue::enqueue`), as `set_loops` on the same entry always did; it used to be
  accepted and ignored.
* **Foreign-loop awaits fail deterministically** (§9.10 rule 2). Every awaitable of the streams,
  playbacks, track handles and their context managers calls `_Pump.check_loop()` first, before its
  synchronous fast path; before, the `RuntimeError` came only when the call had to wait, and a
  foreign-loop `seek()` performed the seek and then raised.
* **Router refusals are logged.** A stream `listen_users` cannot create (64-stream cap, receive
  budget, wake ids) is still counted in `UserStreams.dropped` and not retried until the user leaves,
  and now also logs a warning (`discord.ext.songbird.native.rx.pipeline`). `dropped`'s docstring
  named only the router-queue overflow.
* Already fixed by the send review (`W4.md` §9): `EncodedStream`/`OpusPacketStream.__aexit__`
  close at once on an exception or cancellation, and their drains are bounded.

## 2. Docs

* `close()` of an `AudioStream`/`EventStream` frees what is queued and ends iteration at once (the
  real module always did; the docs, `examples/echo.py` and the fake said the queue drains). A close
  by the connection, a leave or the router keeps queued chunks readable.
* `AudioFile.from_path` points at `load_audio_file` (there is no `AudioFile.load`).
* `__all__` lists `load_audio_file` and the public type aliases (`FormatLike`, `Encoding`,
  `Overflow`, `MixPolicy`, `UserLike`).
* receive.md has a "Limits" section (64 streams shared with `listen_users`, 64 routers, 16 event
  streams, `max_receive_mb`, what happens to a refused speaker).
* `audioop-lts` is no longer a direct dependency but is still installed: discord.py 2.7.1 requires
  it on Python ≥ 3.13.

## 3. Test hooks and the fake

* Detached connections answer `info()`/`seek()` from the track's `FakeTrackControl` (which now keeps
  volume, loops and the last seek position), so the binding's result conversion (`TrackInfo`,
  seconds, `TimeoutError`, `TrackError`) runs on the real module. `_testing.set_ops_answered(conn,
  False)` makes them time out as on songbird's parked mixer; `_testing.fail_track(track, message)`
  ends a track `"error"` as songbird's `TrackEvent::Error` would.
* The pure-Python fake now matches the real module where it differed: an explicit `close()` frees
  queued chunks and events; `listen_user(0)` raises `ValueError`; `RawPcm` and `from_samples` reject
  a partial frame; `read_batch` caps at 6000 chunks; receive-off connections still take mappings and
  leaves; router refusals are counted, logged and not retried; `set_bitrate` on a closed connection
  raises `ConnectionClosed`. `tests/test_parity.py` runs these checks in both modes.

## 4. Tests

* `test_logging.py`: real-module forwarding (logger name, `rust_target`, level) and Rust-side
  filtering are asserted, not only the absence of secrets; `conftest.flush_native_logs()` stops and
  restarts the forwarder (which drains the ring before it exits) instead of sleeping. The leak test's
  "no ERROR records" check uses it too.
* `test_cancellation.py`: the write test frees space at random moments (so writes complete, and are
  cancelled after their wake-up) and asserts `written_ms == 100 + 40 × completed`; the event test
  injects during pending waits and asserts received + remaining is exactly the injected sequence.
* `test_options.py`: creation-time options of `listen_mixed`, `listen_users`, `UserStreams.close`,
  `open_playback(when_disconnected=, auto_pause=)`, `set_bitrate`, `EncodedStream.finish`, the
  `TrackEnd("error", message)` path and `configure_runtime` after the first connection.
* `test_receive.py`: the `listen_users()` default-format check reads a routed stream's chunks.
* `test_config.py`: every name the README, user docs and examples use is in `__all__`.
