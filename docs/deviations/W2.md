# W2 deviations from `docs/design.md`

Workstream W2 (events, ctrl, conn, tracks, and the binding files `src/py/{connection,events,tracks}.rs`).
Phase 0b created every §12.3 item at its contract signature; phase 1 implemented the bodies. This file
lists everything that differs from, or adds to, the letter of §4–§8 / §12.3 / §12.6, with the reason.
No shared file (`Cargo.toml`, `crates/sbcore/Cargo.toml`, `crates/sbcore/src/lib.rs`, `src/lib.rs`,
`src/py/mod.rs`, W1 files) was changed in phase 1.

## 1. Lint allowances

* The phase-0 `#![allow(dead_code, unused_variables)]` headers are gone from every W2 file.
* `ConnWorker::run` keeps the contract signature `pub fn run(self) -> impl Future<Output = ()> + Send`
  with `#[allow(clippy::manual_async_fn)]`: the explicit `+ Send` bound is part of the API, which an
  `async fn` cannot state.

## 2. State machine (`conn/gateway.rs`, §4.5)

Implemented row by row; the table tests enumerate every phase class (Idle, Joining, Joining with the
move fallback armed, Connecting, Connected, AwaitingMove, AwaitingRejoin, Rejoining, Closed) × 29
representative inputs, asserting the resulting phase **and** the action list of every listed pair and
"no actions, no change, unlisted counter + 1" for every other pair. Differences from the letter:

* **Every transition into `Closed(r)` yields exactly `[Teardown(r)]`.** The table's
  `Emit(Disconnected{will_retry:false})` and `Control(Closed)` are performed by teardown (T6 appends
  `Disconnected{reason: r, code, will_retry:false}` to every event queue, T8 sets the sticky `Closed`
  slot). Emitting them from the step as well would deliver `Disconnected` twice, and §8.11 requires it
  to be the last event, which only T6 can guarantee.
* **`NotifyStatus` on every public-state change.** A step that changes `status().state` appends
  `NotifyStatus` (unless it closes: T9 rings `WAKE_CONN`), so any Python `wait_status` predicate is
  woken; the table lists it only for `Connected`.
* **`Connected` → `AwaitingRejoin`** (driver disconnect of kind `Runtime`/`Reconnect`) also emits
  `RxLink{up:false}` and `Emit(Disconnected{reason, code, will_retry:true})`, like the 4014 row. The
  media link is down in that phase; without `RxLink` the housekeeper's `when_disconnected` policy would
  never see it.
* **`AwaitingMove` stores a `VoiceServer(Some)`** (no actions, no phase change): Discord may send the
  server update of a move before its `VoiceState`. Entering `AwaitingMove` moves the current server
  to the fallback slot, so a server stored there is fresh; the following `VoiceState(c' ≠ channel)`
  then connects at once, otherwise it arms the 3 s fallback with the previous server.
  `AwaitingMove` + `VoiceState(same channel, new session)` connects with the stored or previous server.
  The move is reported with `Control(ChannelMoved)` like the other external-move rows.
* **`AwaitingMove` + `VoiceState(None)`** closes with `Requested` after `request_leave()`
  (`Kicked` otherwise).
* **`rejoin_attempts = 0` disables gateway rejoins everywhere.** A rejoin is scheduled only while
  `reconnect` and `attempt + 1 ≤ rejoin_attempts` (the `Connected` rows say only "if reconnect").
* **Unchanged `VoiceServer` in `Connecting`/`Connected`** is an unlisted pair (the rows say
  "changed"). **`VoiceServer(None)` disarms the move fallback** (Discord announced a reallocation).
  **An unnormalisable endpoint** (`""`, `"wss:///"`) is treated as `endpoint=None`.
* **`DriverDisconnect` with `reason: None`** (songbird: "requested in some way") is ignored like
  `Requested`, for every kind. `DriverDisconnect{Connect, _}` outside `Connecting`/`AwaitingMove` is
  unlisted.
* **In `Rejoining`** a `VoiceState` naming another channel keeps an already received (fresh) server;
  in `Joining` it is discarded as the table says.
* **`Disconnected.reason` strings** of driver disconnects are `DiscReason::as_str()`
  (`"ws_closed"`, `"io"`, `"timed_out"`, `"protocol_violation"`, `"internal"`, `"attempt_discarded"`,
  `"other"`); `code` is the voice close code. `close_code` of a `Lost` close after a WS close (incl.
  the 4014 grace expiry) is that code, although `CloseReason::Lost` carries none.
* **Backoff jitter is deterministic** (SplitMix64 of guild id, generation and attempt; ±20 %), so
  `step` stays pure and tests can bound it.
* `Connected.timeline_ms` is filled in by the executor (`Emit`), not by the pure step.
* Additions: `Phase::is_open`, `DiscReason::{as_str, code, from_songbird}`, `DiscKind::from_songbird`,
  `GatewayState::{phase, unlisted_inputs, backoff}` (pub), `pub(crate) force_close` (T1, keeps the
  first reason), `GatewayState: Clone`.

## 3. Apply discipline, teardown, Driver (`conn/shared.rs`, `conn/driver.rs`, §4.6–§4.8)

* `apply`/`run_pending`/`execute` follow §4.6 verbatim. Every Driver call goes through a private
  `with_driver(|d| …)` that holds L1 only for the flume send; nothing else (in particular no L2 and no
  `apply`) is called under L1. In tests the executor records `Connect` generations and `RxLink`
  sequence numbers (`cfg(test)` only) for the ordering stress test.
* `close()` runs T0–T9 in order. In a foreign process (fork) it returns right after T0 and leaks
  everything (T1 too: a lock may be held by a thread that does not exist in the child). T7 aborts the
  connect tasks; op tasks are aborted by `OpRegistry::fail_all` (T8). T8 also resolves pending queue
  entries (`TrackQueue::close_all`) and rings `WAKE_OPS` (failed op results must reach Python).
  `ConnShared: Drop` calls `close(Dropped)` (idempotent).
* `pub(crate) fn connect_deadline(s, reconnect) -> Duration` (§4.8 formula). A `Connect` future
  failing with `AttemptDiscarded` maps to `ConnectFailure::AttemptDiscarded`, a timeout to `TimedOut`.
* `play()` rejects `SourceSpec::Encoded` with `Track` (encoded streams are queue-only); it checks
  volume and loops before registering anything, and `MAX_PLAYING_TRACKS_PER_CONN` before building the
  input.
* `set_bitrate(None)` sends songbird's `DEFAULT_BITRATE` (`Bits(128_000)`).
* `subscribe` counts open subscription queues against `MAX_SUBS_PER_CONN`; routers are capped by the
  same constant separately (`subscribe_router` validates its stream parameters through an equivalent
  `SubSpec`). A subscription created while the connection closes is closed immediately and refused.
* **Race-free I6 admissions** (`conn/admission.rs`, a private submodule): `MAX_PLAYING_TRACKS_PER_CONN`
  (`play()` and the queue's `advance`), `MAX_LIVE_SOURCES_PER_CONN` (`open_*`) and `MAX_SUBS_PER_CONN`
  (subscriptions, routers) count the visible items **plus every in-flight reservation**; a
  reservation is released only after its item became visible. A plain count-then-insert let N
  free-threaded callers that all saw `max − 1` insert N items. Near the bound a concurrent admission
  can be refused spuriously (counted twice), never admitted beyond it.
* **`run_pending` is unwind-safe**: a guard clears `executing` if an action unwinds (the panic still
  reaches the caller's `catch_unwind`/pyo3). A stuck flag would have queued every later batch forever.
* **Fork (§4.10)**: `ConnShared: Drop` in a foreign process leaks the inherited Driver
  (`mem::forget`) instead of dropping it (`Poison` would take flume/tokio locks a vanished parent
  thread may hold); `close()` already skipped T1–T9 there. Unit tests run in the creating process,
  so under `cfg(test)` the "leaked" Driver is parked in `LEAKED_DRIVERS` for the test to tear down.
* `stop_all()` calls `TrackQueue::stop()` (clear + skip) instead of `clear()`, so an entry that the
  worker is starting at that moment also ends.
* A track op (`start_track_info`/`start_track_seek`) registered after T8's `fail_all` is failed at
  once (`ConnectionClosed`) instead of running until its timeout.
* `GatewayState`'s `Debug` never prints the token (`<redacted>`) or the session id (length only).
* Test-only constructors: `new_unspawned` (worker returned, real Driver) and `new_with_pid`.
* Additions: `ConnShared::{is_detached, guild_id, user_id}`; `stats()` reports `ticks_real,
  ticks_synthetic, ticks_dropped, ticks_skipped, bad_packets, decode_errors, plc_frames,
  carry_overflow_frames, dave_trailers_stripped, decoders_active, subscriptions, routers, lanes,
  dispatch_reinstalls, dispatch_panics, ctrl_dropped, heartbeat_misses, panics, connects, rejoins,
  stale_connects_dropped, gw_unlisted_inputs, pending_ops, receive_budget_bytes` (`log_dropped` is not
  reported per connection: `native._log_dropped()` owns that counter).

## 4. Dispatch and worker (`conn/dispatch.rs`, `conn/worker.rs`, §8.2, §8.8)

* `Dispatch` stores the heartbeat as milliseconds since its own creation (`last_heartbeat()`); the
  worker's handler-liveness watchdog runs only while a Driver exists, applies `HandlersLost` at most
  once per second while the gap lasts (the state machine rate-limits the reinstall to 5 s) and counts
  `heartbeat_misses`. Verified with a real Driver: `Periodic(1 s)` fires from a parked mixer.
* **The worker emits `ReceiveStalled`** (once per stall, when `RxTimer.stalled_since` first becomes
  `Some`) and feeds `RxStalled{since}` at most once per second while it lasts. W3's pipeline must not
  emit it.
* Caught panics (dispatcher, worker step) log at ERROR at most once per minute per site
  (`conn::LogLimiter`, a crate-private helper in `conn/mod.rs`).
* `WorkerShared` additions: `wake()`, `open_queues()`, `open_routers()`, `timeline_ms()`,
  `rx_counts()` (published by the worker after every step), panic / heartbeat-miss counters. `push`
  after `shutdown()` drops the command; `shutdown()` drops pending commands. `close_queues` closes
  routers with `close(true)`. Per step the worker takes at most `2 × TICK_CHANNEL_CAP` inputs and
  re-polls immediately if more are queued.

## 5. Events and control slots (`events.rs`, `ctrl.rs`, §6.4, §8.11)

* `Lagged{dropped}` is synthesised before the next event only if the queue's mask selects `Lagged`
  (`KindMask::LAGGED`); `dropped()` counts regardless. `EventQueue::close()` (subscriber side) frees
  the queued events at once; T6's `close_all(last)` keeps them readable and appends `last` even if the
  mask does not select it and even if the queue is full (the oldest event is evicted, counted as a
  drop). Additions: `EventHub::{is_closed, open_queues}`, `EventQueue::{is_closed, len, is_empty}`.
* `CtrlQueue`: `Closed` is level-triggered — once set it is reported by **every** `take()` (it is
  "sticky"), keeps its first reason, and suppresses `Rejoin`. `take_up_to(max, out)` leaves the slots
  beyond `max` pending (`ConnShared::take_controls(max, …)`); `closed()` added.

## 6. Tracks (`tracks/*`, §7.10)

* **Polled list.** `TrackRegistry::register` no longer adds the flags to a list: only started tracks
  (`bind`/`mark_started`) and pending entries resolved by the queue (`watch`) are polled, and a track
  leaves the list once its `TrackEnded` was reported. 10 000 pending queue entries therefore cost
  nothing per tick. `needs_poll()`, `is_closing()`, `pub(crate) {mark_started, watch}` added.
* **Delayed finalisation** counts ticks from the first housekeeping pass that observes `DROPPED`
  (`DoneGuard::drop` stays atomics-only and does not know the tick); the track resolves 2 ticks later
  (`TrackFlags::finalise_dropped`). The housekeeping tick is `(now − t0) / 20 ms` of the connection's
  clock, so it works with the manual clock.
* `TrackFlags` additions: `is_started`, `conn_closing`, `pub(crate) {mark_started, set_watched,
  take_report, is_reported, finalise_dropped}`; `error()` returns the text only for an `error` end.
* `TrackRef` additions: `pub(crate) new`, `same`, `is_started`, and the controls `pause`, `resume`,
  `stop`, `set_volume` (checked against `VOLUME`), `set_loops` (`Track` for live sources), which use
  songbird's handle or, on a detached connection, the fake. Under `test-hooks` the struct has a third
  field `pub fake: Arc<OnceLock<Arc<FakeTrackControl>>>` and `fake_log()` (what
  `native._testing.track_log` should return). `pub fn tracks::loop_state(Option<u32>)` added.
* `TrackQueue` is one L10 lock (items + current) plus the `paused` atomic. Additions:
  `pub(crate) attach(registry, worker)` (called once by `ConnShared::new`: removed pending entries are
  reported as `TrackEnded`, enqueue/resume wake the worker), `pending_opts`, `is_paused`,
  `pub(crate) {take_stream, needs_advance, close_all}`. Behaviour:
  * `skip()` stops the current track **and resolves it `stopped` at once**, so the queue advances even
    while the mixer is parked (songbird processes track commands only on a live mixer).
  * `advance` waits while `MAX_PLAYING_TRACKS_PER_CONN` `play()` tracks are playing (the current entry
    counts towards the limit); an entry whose input fails to build resolves `error` and the queue moves
    on (at most 64 failures per tick).
  * A `PendingChange` made while the popped entry is being started is applied right after it started;
    a skip during that window stops the new track.
  * `update_pending` validates volume/loops (`Limit`/`Track`).
  * `enqueue` checks `closing` **under the queue lock**: checked before it, an entry could be added
    after T8's `close_all` and never end.
  * `remove(t)` (`NativeTrack.stop()` on a not-started track) also covers the current entry while
    the worker is starting it: it is resolved `stopped` at once and `advance` stops it right after
    the start (as `skip()` does). Before, such a `stop()` was silently lost.
  * `pause()`/`resume()` record the change for an entry that is being started (applied after the
    start) instead of failing silently on the not-yet-started track.
  * An entry that fails to start because the connection closed meanwhile resolves `disconnected`,
    not `error`.
* `TrackRegistry::watch` (every start path: `bind`, `mark_started`) resolves the track
  `disconnected` when the connection is closing: a `play()`/`open_*`/queue start racing `close()`
  could bind its track after T8's `finish_all` swept the list, leaving it unresolved forever.

## 7. Detached connections (feature `test-hooks`, §13.2)

* `ConnShared::new_detached` builds everything except the Driver; `conn/detached.rs` (a private
  submodule) parks the songbird `Input` of every started track (pruned when the track ends) and gives
  the track a `FakeTrackControl` (shared between the `TrackRef` and the source's
  `Box<dyn TrackControl>`). `stop_all` and T8 drop the parked inputs (real `DoneGuard` path).
* `Connect` actions succeed instantly on a detached connection (the step's `ConnectResult{gen, Ok}` is
  applied right after the batch) unless `set_detached_auto_connect(false)`.
* Test-hook API for W5: `ConnShared::{set_detached_auto_connect, inject_gateway(GwInput),
  inject_driver_connect(ssrc, reconnect), inject_driver_disconnect(kind, reason), rx_sender(),
  take_parked_input(&TrackRef)}` and `conn::take_parked_live_input(source_id)` (searches the registry;
  `MixerHarness::take(playback)` passes `LiveSource::id(playback)`). Driver events go through the same
  `DispatchInner` paths `act` uses (`apply` + `RxInput::LinkUp/LinkDown`).

## 8. Binding (`src/py/tracks.rs`)

* `NativeTrack` controls use the `TrackRef` methods (so they also drive the detached fake);
  `pending` = not started and not ended. A pending-entry change that loses the race with the entry
  starting is applied to the started track instead of raising. `stop()` is idempotent: it removes a
  pending entry, stops a started track and ignores songbird's `Finished` for an already ended one.
  Docstrings and signatures are unchanged (no stub drift).

* Review fixes (verified by loading a `test-hooks` wheel into a scratch interpreter, 3.14t):
  `Connection.take_ready()` returns `list[int]` as §12.6 and the stub say (a `Vec<u8>` became
  `bytes` in pyo3); `enqueue`/`enqueue_stream` after close raise `ConnectionClosed` with the
  connection's close reason (like every other method) instead of `"connection_closed"`;
  `VoiceSettings(driver_retries=0)` keeps its `LimitExceeded` fields and adds an exception note that
  explains why 0 is refused (§4.8, §13.5).

## 9. Integration points left for phase 2 (other workstreams' contracts)

* **W4:** `OpusQueue` and `EncodedShared` have no way to receive their `TrackControl`
  (`PcmQueue::attach_track` exists). `open_opus_stream`/`open_encoded` hand the paused track to
  songbird but drop the control (`_ctl`), so nothing would resume them until an `attach_track`-like
  method exists. A lazy `Encoded` queue entry is started unpaused (unless `paused=True`) for the same
  reason.
* **W3:** router-created subscriptions must be registered with `WorkerShared::register_queue` (T6
  closes them and they count towards `MAX_SUBS_PER_CONN`), and the pipeline must bound the
  `unclassified` list it shares with `ConnShared`. `ReceiveStalled` is emitted by the worker (§4).
* **W5:** `Harness::detached` can build on `ConnShared::new_detached`; `testing::track_log` on
  `TrackRef::fake_log`; `inject_*` on the §7 API.

## 10. Phase-0 notes still valid

* `registry_snapshot()` / `shutdown_all(reason)` live in `conn/registry.rs` and are re-exported from
  `conn::shared` and `conn`; `native._shutdown_all()` calls `sbcore::conn::shutdown_all(ProcessExit)`.
* `conn::settings` keeps the per-field ranges as `pub const`s; `VoiceSettings::validate` reports a
  duration that is not a multiple of 20 ms as `InvalidAudio` (no generic invalid-argument variant).
* `EventSubscription` holds only `queue: Arc<EventQueue>` (no `Weak<EventHub>`); the hub prunes
  closed queues on every `emit` and `subscribe`.
* Binding surface: `VoiceSettings` is the Rust struct `PyVoiceSettings`; keyword-only constructor with
  the §9.3 defaults; integer arguments are checked before narrowing (`LimitExceeded`, never
  `OverflowError`); `Control.ClassifyUsers` is the empty struct variant `ClassifyUsers()`; the
  `reason` fields of `Control.Closed` / `VoiceEvent.{Disconnected, PlaybackEnded, TrackEnded}` are
  owned `String`s (pyo3 complex-enum constructors need `FromPyObject` fields);
  `VoiceEvent.SpeakingStarted.captured_at` is a `time.monotonic()` float; `take_controls()` drains
  every slot; `queue_dequeue(i)` raises `IndexError` for a negative index.

## 11. Test-hook skeleton notes from phase 0b (W5 files `crates/sbcore/src/testing/*`, `src/py/testing.rs`; unchanged)

* `native._testing` is a declarative submodule (`#[pymodule(submodule, name = "_testing",
  gil_used = false)]`) registered only under `test-hooks`; classes use
  `module = "discord.ext.songbird.native._testing"`; no stubs are generated (§12.6 Stubs rules).
* `detached_connection(guild_id, user_id, settings, bell=None) -> (Connection, Harness)`: an optional
  `bell` was added (§12.6 lists no doorbell argument); `None` means the harness creates its own
  doorbell and tests poll `take_ready()` directly. sbcore entry point:
  `pub fn testing::Harness::detached(guild_id: NonZeroU64, user_id: NonZeroU64,
  settings: VoiceSettings, bell: Option<Doorbell>) -> Result<(Arc<ConnShared>, Harness), CoreError>`
  (it will build on `ConnShared::new_detached`); `Harness::step(&self, advance_ms: u64) ->
  Result<(), CoreError>`, `Harness::clock()`.
* `inject_driver_event(conn, kind, reason=None, code=None, ssrc=0)`: `kind` is `"connect"`,
  `"reconnect"`, `"disconnect"` (= runtime) or `"disconnect:connect|reconnect|runtime"`; `reason` is
  a `DiscReason` name (`"ws_closed"` uses `code`); `ssrc` was added for connect/reconnect. sbcore:
  `pub enum testing::DriverEvent { Connect { ssrc }, Reconnect { ssrc }, Disconnect { kind, reason } }`,
  `inject_driver_event(conn: &ConnShared, ev: DriverEvent)`.
* The injection functions take owned `Vec<u8>` payloads (`inject_tick(conn, voices: Vec<(u32,
  Option<Vec<u8>>)>, silent: Vec<u32>)`, `inject_voice_tick_rtp(conn, packets: Vec<(u32, Vec<u8>)>)`)
  because the binding has no `bytes` dependency.
* `testing::MixerHarness::take(playback: &Arc<PcmQueue>) -> Result<Arc<Self>, CoreError>` and
  `pull(&self, ticks: usize, out: &mut Vec<f32>)` (interior `Mutex`, so the pyclass holds only an
  `Arc`); Python `MixerHarness(playback).pull(ticks)` returns little-endian `f32` bytes.
* `testing::{track_log(&TrackRef) -> Vec<&'static str>, alloc_count() -> u64}`, `testing::rtp::{RtpOpts,
  encode_opus, rtp_wrap}` (both return `Result` so they can be stubs).
